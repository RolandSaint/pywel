# Portability

The portable knowledge format is UTF-8 JSON and JSONL, with local schemas, vocabulary, licenses, and checksums. A consumer can use these files without Node, an account, a database, network access, or a Pywel server. Register the included JSON Schemas by `$id` and resolve `$ref` locally; HTTPS schema identifiers are not a hosted-service requirement. OpenAPI, response schemas, and the compact codebook explain the same agent contract used by the reference adapters.

Building and running the reference implementation uses Node **24.18.0**, pinned in `.node-version` and `.nvmrc`, plus the checked-in npm lockfile. The builder records the Node version in its identity. File consumption is independent of that build toolchain. The supported server interfaces are local loopback REST and stdio MCP; both validate canonical JSON at startup and read its public projection.

Run the [operations procedure](OPERATIONS.md) from a reviewed Git working checkout. `dist/data/` is the self-describing offline bundle; `dist/runtime/` is compiled reference code and still needs installed runtime dependencies, canonical data, schemas, and the project source context. Neither a lone JavaScript file nor an unverified container is an installation package.

The clean public-source snapshot excludes original private Git history, refs, releases, assets, settings, and caches. It includes safe canonical source and an exact checksummed inventory. It is a representation of one reviewed GitHub revision, not a second ongoing authority. Preserve this export unchanged: its exact `SOURCE_MANIFEST.json` guard correctly rejects installed dependencies, generated output, and Git metadata. The [export-to-checkout commands](OPERATIONS.md#immutable-source-export-and-working-checkout) verify the trusted candidate manifest digest and exact file bytes using Node built-ins, copy only enumerated source files into an absent destination, and initialize local Git history without personal identity settings. Keep the manifest with the immutable export. Save the baseline's declared hashes before proposing a correction; even documentation changes affect source-build identity, so restore exact prior source before comparing its artifacts. Never remove the export's manifest or relax its guard to turn it into a mutable checkout.

Required build/read operation makes zero paid model calls and provisions no service. There is no supported Docker, SQLite, HTTP MCP, Cloudflare, hosted URL, domain, or personal-system dependency. Add another packaging or hosting path only after a concrete consumer need justifies its maintenance cost.

M2 exercises the local reference path; M3 adds the typed response, bounds, context, and compatibility contract. [M4 evidence](M4_COMPLETION.md) records another assistant operator verifying the immutable export, preparing separate Git checkouts, reproducing, querying, applying a reviewed correction, and restoring the named candidate. The proof uses the same managed Linux environment and cached public packages; it does not claim another operating system or a cold toolchain download. [M5 acceptance](M5_COMPLETION.md) records software 1.0.0 as PUBLIC RELEASE READY for the named clean source snapshot and artifacts, using applicable M4 evidence and final candidate checks. The public repository begins with the verified clean source; its v1.0.0 release notes record the publication source, artifacts, and verification.
